# KH_Aw Capability, Tool, and Independent AI Enforcement

## Capability rule

KH_Aw requires behavior, not an invented command name. `/goal`, `/plan`, or `/review`
may be preferred where available. Context inspection, delegation, research, artifact
creation, change inspection, and tests can be satisfied by physical Codex tool/subagent
receipts when the active surface has no matching slash command.

Every record needs a real file, hash, invocation, and tool or session relation. A prose
claim cannot pass.

## Independent workers

Every stage retains one lead and 2-60 dynamically calculated workers. Workers require
immutable dispatch contracts, independent Codex session IDs, unique outputs, invocation
receipts, ring cross-review, and lead aggregation. `native-agents`, `codex-subagent`,
and `independent-task` receipt modes are accepted; none can be replaced by self-review.

## Target tools

- Web: build, lint, unit tests, browsers, accessibility, responsive, console/network,
  visual regression, Lighthouse.
- Android: Gradle, unit/lint/screenshot tests, emulator health, screenshots, Logcat.
- iOS: Xcode build/tests and Simulator.
- Codex plugin: security scan, Python tests, Node syntax, plugin doctor, deterministic
  packaging.

APK installation commands remain blocked. Tool output retains cwd, command, exit code,
stdout/stderr log, artifact paths, and hashes.
